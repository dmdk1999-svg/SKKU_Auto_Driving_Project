# 8. 진출로 정체 구간 강제 끼어들기 시나리오 계획 — 한남대교 남단 나들목

> 최초 작성: 2026-11-16 · 개정: 2026-11-19 (문제 정의를 "강제 끼어들기"로 변경)
> 상태: **계획 (미구현)**
> 기준 코드: 커밋 `3210488` 이후 작업 트리 (`env/road_config.py`의 `ROAD["osm"]`, 생성된 `env/sumo/highway.net.xml`)
> 참고 자료: 팀 내부 문서 「정체 행렬 끼어들기(앞머리 진입) 구현 가능성 검토」(2026-11-09)

## 0. 문제 정의

### 0.1 상황

한남대교 · 경부고속도로 · 올림픽대로가 만나는 나들목처럼, 실제 도로에서는 **진출로로 가는 차로 하나만 길게 정체되고 나머지 차로는 원활하게 흐르는** 경우가 자주 생긴다. 이때 지하차도를 막 빠져나왔거나 길을 처음 가는 운전자는, 이미 줄이 길게 이어진 정체 차로 옆에 뒤늦게 도착하게 된다.

이 프로젝트에서는 다음 조건을 전제로 한다.

- 정체는 **진출로와 그 앞 본선 맨 우측 차로에만** 있다. 다른 차로는 제한속도 가까이로 흐른다.
- ego는 줄의 꼬리보다 앞쪽에 나타나기 때문에 **줄 맨 뒤에 붙는 선택지는 없다.**
- ego는 진출로로 가야 하므로 **반드시 줄 중간에 끼어들어야 한다.** 진출부를 지나치면 실패다.

### 0.2 AV가 해야 하는 의사결정

1. 흐르는 차로를 가로질러 정체 차로 바로 옆 차로로 이동한다.
2. 정체 차로의 속도에 맞춰 감속하면서, 어느 틈을 노릴지 고른다.
3. 줄 앞부분이 출발해 틈이 벌어지는 순간, **앞머리를 일부만 걸쳐(앞머리 진입)** 끼어들 의사를 보인다.
4. 뒷차의 반응을 보고 판단한다. 감속해서 양보하면 몸통까지 넣고, 따라붙으면 물러나 다음 틈을 노린다.
5. 이 모든 과정을 진출부에 도달하기 전에 끝낸다.

### 0.3 기존 환경으로 풀 수 없는 이유

지금 환경의 차선변경은 LC2013 모델과 TraCI `changeLane`을 쓰고 있어, 차선이 한 스텝에 통째로 바뀐다. 이 방식에서는 차 길이와 안전거리를 합친 만큼의 빈자리가 있어야 차선을 옮길 수 있다. 촘촘한 정체 줄에는 그런 빈자리가 거의 생기지 않으므로, 현실적인 끼어들기를 표현할 수 없다. 팀 내부 검토에서 sublane 모델(SL2015)을 쓰면 차 길이보다 짧은 틈(3.4m)에 앞머리를 걸쳐 끼어들 수 있음을 확인했다.

### 0.4 이 문제를 RL로 푸는 이유

틈이 생겨도 끼어들 수 있느냐는 결국 **뒷차가 양보하느냐**에 달려 있다. 뒷차의 양보 성향은 겉으로 드러나지 않으므로, ego는 뒷차의 움직임(차간거리, 출발 반응, 감속 여부)을 보고 추측해야 한다. 이 프로젝트의 문제는 **정답 정보가 관측에 없는 부분 관측(POMDP) 문제**로 설명할 수 있다.

차로당 유량이 대략 1,200대/시간 이하면 자유 흐름으로 볼 수 있다. 정체 차로(0번)를 뺀 나머지 차로가 이 유량을 받아도 여유가 있어야 한다.

| 본선 구간 | 합계 (대/시간) | 차로 | 전 차로 기준 차로당 | 0번 차로 제외 시 (직진 차량만, 4차로) |

| R1 `46676451#0` | 2,700 | 5 | 540 | 1,800 / 4 = 450 |
| R2 `46709879#0` | 3,000 | 5 | 600 | 2,300 / 4 = 575 |
| R3 `524280032#0` | 2,100 | 5 | 420 | 1,400 / 4 = 350 |

→ 0번 차로가 정체 줄로 막혀도 **나머지 차로는 자유 흐름을 유지할 수 있다.** 본선 유량은 그대로 둔다.

## 2. 정체 줄 만들기

### 2.1 정체 줄의 모양

```
 SUMO 4번 (한국식 1차로) ══════════════════════════════════════  (흐름)
 SUMO 3번               ══════════════════════════════════════  (흐름)
 SUMO 2번               ══════════════════════════════════════  (흐름)
 SUMO 1번               ════════════════ ego가 기다리는 차로 ══  (흐름, ego가 일시적으로 막을 수 있음)
 SUMO 0번               ═══ ▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪▪╲
                            └ 꼬리     본선 넘친 구간     진출부 ╲▪▪▪▪▪▪▪▪▪▪▪|게이트| → 합류 (원활)
                                                                    램프 단독 구간
```

- 램프 단독 구간 전체와 **본선 0번 차로의 일부(넘친 구간)**가 정체 줄이 된다.
- 넘친 구간 길이(진출부에서 꼬리까지)는 R1·R2에서 250~450m, R3에서 150~300m를 목표로 한다.
- 0번 차로 외의 차로에는 정체가 생기면 안 된다.

### 2.2 방출 게이트

램프 단독 구간의 끝에 가상의 정지선(게이트)을 두고, 일반 차량을 일정 간격으로 한 대씩 내보낸다.

| 램프 | 게이트 위치 | 비고 |
|---|---|---|
| R1 | `46623306#0` 끝에서 5m 앞 | 공유 합류점(`59054218`)보다 앞이라 `olympic_w_gyeongbu`는 영향을 받지 않는다 |
| R2 | `59054214` 끝에서 5m 앞 | |
| R3 | `1028457407` 끝에서 5m 앞 | 공유 분기점(`59054211`)보다 뒤라, 대기열이 분기점을 넘지 않게 해야 한다 (2.4절) |

게이트를 이렇게 쓰는 이유는 두 가지다.

1. **끼어들 기회가 생긴다.** 한 대가 출발할 때마다 출발 파동이 줄 뒤쪽으로 전해지고, 그 파동이 지나는 자리에서 차 사이가 잠깐 벌어진다. 이 틈이 끼어들기 기회가 된다.
2. **줄 길이를 조절할 수 있다.** 넘친 구간 길이를 재서 방출 간격을 바꾸면 줄 길이를 목표 범위 안에 묶어 둘 수 있다.

신호등을 쓰는 실제 램프미터 방식은 쓰지 않기로 했다. ego는 `speedMode=0`이라 빨간불을 무시하기 때문이다.

### 2.3 게이트 제어 로직 (매 스텝)

```python
# 1) 게이트 구간에 들어온 일반 차량(ego 제외)에 정지 예약
for vid in 새로_진입한_차량(gate_edge):
    if vid != ego_id:
        traci.vehicle.setStop(vid, gate_edge, pos=gate_pos, laneIndex=0, duration=1e5)

# 2) 넘친 구간 길이: 진출부에서 본선 0번 차로를 거슬러 올라가며,
#    속도 < 2m/s 인 차량이 이어지는 마지막 차량의 뒤 범퍼까지 거리
spill = spill_length(diverge_edge, lane=0)

# 3) 방출 간격 결정 (피드백)
if   spill < spill_low:   period = release_slow     # 12s: 줄을 늘린다
elif spill > spill_high:  period = release_fast     # 3s : 줄을 줄인다
else:                     period = release_nominal  # 6~9s, 에피소드마다 샘플
if spill > spill_limit:   게이트_전면_개방()          # 비상 조치

# 4) 방출: 마지막 방출 후 period가 지났으면 맨 앞 차량 출발
if 경과시간 >= period and 정지중인_맨앞차량:
    traci.vehicle.resume(맨앞차량)
```

- ego는 정지 예약 대상에서 뺀다. ego가 게이트 맨 앞에 도달하면 그대로 통과시킨다.
- `env/sumo_env.py`에 `RampGate` 클래스로 분리해 warmup 루프와 `step()`에서 매 스텝 호출하는 구조로 만들 계획이다.

### 2.4 "0번 차로만 막히게" 하는 장치

| 장치 | 내용 |
|---|---|
| 직진 차량 차로 정리 | 진출하지 않는 일반 차량이 0번 차로에서 꼬리 뒤에 갇히지 않도록, 꼬리 300m 앞부터 0번 차로에 있는 직진 차량은 TraCI `changeLane`으로 1번 차로 이상으로 옮긴다 |
| 비상 개방 | 넘친 구간이 상한(R1·R2 500m, R3 330m)을 넘으면 게이트를 전면 개방한다 |
| 공유 구간 보호 | R3은 줄이 진출 후 공유 구간까지 차는 구조라, `59054211` 분기점이 막히면 `hannam_olympic_w` 차량도 갇힌다. 분기점 직전에서 `hannam_olympic_w` 차량은 줄을 건너뛸 수 있게 처리하거나, R3을 보조 시나리오로만 쓴다 |
| 순간이동 | SUMO 기본값은 300초 이상 멈춘 차량을 순간이동시킨다. `--time-to-teleport 600`을 주고 순간이동 횟수를 기록한다 |

### 2.5 정체 줄 차량 배치

| 대상 | 수요를 늘릴 flow | 기본값 | 정체 시 값 | 기본 방출량 (간격 7.5초) |
|---|---|---|---|---|
| R1 | `olympic_e_gyeongbu` | 900 | 1,000 | 480대/시간 |
| R2 | `olympic_w_hannam` | 700 | 900 | 480대/시간 |
| R3 | `hannam_olympic_e` | 700 | 900 | 480대/시간 |

**에피소드 시작 시 미리 채우기:** warmup만으로 넘친 구간까지 채우려면 시간이 오래 걸린다. 그래서 `reset()`에서 정체 줄을 직접 채우기로 한다.

1. 게이트부터 넘친 구간 목표 길이까지 7.5m 간격(±1m)으로 일반 차량을 `departSpeed=0`으로 배치한다. 각 차량의 출발 구간부터 경로 끝까지 이어지는 route를 `traci.route.add`로 등록해 쓴다.
2. 배치하는 차량에는 5장의 양보 성향을 정해진 비율대로 부여한다.
3. 그 뒤 warmup 동안 본선 교통과 게이트가 자리를 잡는다. 본선만 채우면 되므로 warmup은 300초보다 짧게 줄일 수 있다.

## 3. ego 투입 방식

### 3.1 출발 위치: "줄 꼬리보다 앞"

지하차도를 막 나온 상황을 표현하기 위해, ego를 경로 시작점이 아니라 **정체 줄 옆에서 출발**시킨다.

| 항목 | 값 | 비고 |
|---|---|---|
| 출발 구간 | R1 `46676451#0`, R2 `46709879#0`, R3 `524280032#0` | ego 전용 route를 `traci.route.add`로 등록 |
| 진출부까지 거리 D | 기본 150~300m (R3은 120~250m) | 넘친 구간 길이 ≥ D + 50m가 되도록 맞춰, 꼬리가 항상 ego 뒤에 있게 한다 |
| 출발 차로 | 1~4번 무작위 (평가에서는 3~4번 고정 시나리오도 둔다) | 3~4번 = 한국식 1·2차로 = "지하차도 출구" |
| 출발 속도 | 15~22 m/s (54~80 km/h) | |

이렇게 하면 줄 뒤에 붙는 선택지는 구조적으로 사라진다.

### 3.2 종료 조건

| 조건 | 처리 |
|---|---|
| 충돌 | 실패, 종료 |
| **출구 놓침**: 진출부를 지났는데 ego가 램프에 들어가지 못함 | 실패, 종료, 충돌과 같은 수준의 페널티 |
| 진출 성공: ego가 램프 단독 구간에 들어가 100m를 주행 | 학습에서는 성공으로 종료 |
| 시간 초과 | `max_steps`를 OSM 트랙에서 1,600으로 늘린다 |

**완주 기준:** 램프 안의 대기 시간은 길다 (R1 기준 앞에 60~80대 × 7.5초). 학습은 진출 성공에서 끝내고, 평가와 영상에서는 경로 끝까지 주행시킨다. 평가 때는 ego가 램프에 들어간 직후부터 게이트를 빠른 방출(3초)로 바꿔 대기 시간을 줄인다. 이 처리는 발표에서 숨기지 않고 설명하기로 한다.

## 4. 차량 모델: sublane 전환

### 4.1 설정

| 항목 | 값 | 비고 |
|---|---|---|
| 차선변경 모델 | SL2015 (전체 차량) | 앞머리 진입에 필요 |
| `--lateral-resolution` | 0.4로 시작, 0.1과 비교 | 0.1은 21.7km 도로망에서 느릴 수 있다. 결과가 같으면 큰 값을 쓴다 |
| ego `maxSpeedLat` | 1.0 m/s | 1.4m 걸치기에 약 1.4초 |
| 충돌 판정 | `--collision.mingap-factor 0` | 팀 검토와 같은 기준 (몸체가 실제로 겹칠 때만 충돌) |
| 근접 기록 | 횡간격 < 0.3m이면서 종방향으로 겹침 | 충돌은 아니지만 위험한 상황을 따로 집계 |

SL2015로 바꾸면 **배경차 전체의 차선변경 동작이 바뀐다.** 지금까지 맞춘 교통 흐름(정체가 0번 차로에만 있는지, 직진 차량이 흐르는지)을 다시 확인해야 한다.

### 4.2 미리 확인해야 할 것

- ego의 `laneChangeMode=0` 상태에서 `traci.vehicle.changeSublane()`이 의도대로 동작하는지
- 일반 차량이 일부 걸친 ego를 앞차로 인식하는 최소 깊이 (팀 검토에서 0.8m는 뒷차가 다시 출발해 충돌함 → 뒷차의 `getLeader()` 로그로 원인 확인 필요)
- 게이트 방출 파동이 지날 때 컨트롤러 종류별로 틈이 몇 m나 벌어지는지 (IDM처럼 반응이 빠른 모델은 틈이 거의 안 생길 수 있음)

## 5. 뒷차 양보 모델

### 5.1 원칙

- **성향은 차량을 만들 때 정한다.** 같은 차는 에피소드 내내 같은 성향을 유지한다.
- **실제 양보 여부와 반응 시간은 ego가 그 차 앞에 처음 머리를 넣는 순간 한 번 뽑아 고정한다.** ego가 물러났다가 다시 넣어도 결과가 바뀌지 않는다.
- ego는 둘 다 알 수 없다 (5.4절).

매번 확률을 새로 뽑으면 "물러났다가 다시 넣으면 또 기회가 생긴다"는 허점이 생기고, 정책이 같은 차 앞에서 넣었다 뺐다를 반복하는 쪽으로 학습될 수 있다. 이를 막기 위해 결과를 고정하기로 했다.

### 5.2 성향 정의 (초안, 실험으로 조정)

기존 컨트롤러 4종(Krauss · IDM · EIDM · ACC)과 별개로, 양보 성향을 vType 분포의 추가 축으로 둔다.

| 성향 | 비율 (학습 기본값) | 추종 파라미터 | 머리를 넣었을 때 양보 확률 |
|---|---|---|---|
| 양보형 | 60% | tau 1.2~1.5, 출발 반응 느림 → 틈이 잘 벌어짐 | 0.9 |
| 보통 | 25% | 컨트롤러 기본값 | 0.6 |
| 비양보형 | 15% | tau 0.6, minGap 1.0, 가속 큼 → 앞차에 바짝 붙어 틈이 거의 안 생김 | 0.1 |

비양보형은 추종 파라미터만으로도 틈을 잘 내주지 않는 차가 된다. 이 부분은 SUMO 설정만으로 구현할 수 있다.

### 5.3 양보하지 않는 동작 (TraCI)

SL2015에서는 ego가 앞에 걸치면 뒷차가 이를 앞차로 인식해 감속한다. 이 반응을 끄는 vType 파라미터는 없는 것으로 알고 있으므로, 양보하지 않기로 정해진 뒷차는 TraCI로 속도를 직접 정해야 한다.

```python
# ego가 끼어들려는 차로의 바로 뒷차 f
if f not in decision:                      # 처음 머리를 넣은 순간 한 번만 결정
    decision[f] = {"yield": random() < YIELD_PROB[성향(f)],
                   "delay": uniform(0.5, 2.0)}

d = decision[f]
if d["yield"]:
    if 걸친시간 >= d["delay"]:
        traci.vehicle.setSpeed(f, -1)                     # SUMO 기본 동작: ego를 보고 감속
    else:
        traci.vehicle.setSpeed(f, 원래_앞차_기준_속도(f))   # 반응 전까지 ego 무시
else:
    if 걸친깊이 >= D_FORCE or ego와의_TTC < TTC_MIN:
        traci.vehicle.setSpeed(f, -1)                     # 마지못해 급제동
        forced_brake_count += 1
    else:
        traci.vehicle.setSpeed(f, 원래_앞차_기준_속도(f))   # ego를 무시하고 진행
```

- "원래 앞차 기준 속도"는 ego를 빼고, 같은 차로의 진짜 앞차만 보고 IDM 식으로 계산한 속도다.
- **비양보형도 일부러 들이받지는 않게 해야 한다.** 걸친 깊이가 `D_FORCE`(1.4~1.6m, 실험으로 결정)를 넘거나 TTC가 작아지면 결국 브레이크를 밟는다. 그래야 충돌이 났을 때 "ego가 무리하게 밀어 넣어서"라고 설명할 수 있다. 이렇게 비양보 차량이 급제동하게 만든 횟수는 "무리한 진입" 지표로 따로 집계한다.
- 학습 중에는 비양보형 비율을 에피소드마다 5~30% 사이에서 뽑아, 특정 비율에 과적합되지 않게 한다.

### 5.4 정보 누출 방지

ego는 뒷차의 거리, 속도, 가속도만 보고 성향을 추측해야 한다. 다음 경로로 정답이 새어 나가지 않게 해야 한다.

| 누출 경로 | 대책 |
|---|---|
| 관측 코드 | `_get_obs()`에서 주변 차량의 vType id나 `get_privileged_state()`의 값을 쓰면 안 된다 |
| 차량 id · flow 이름 | 성향이 드러나지 않는 중립적인 이름을 쓴다 |
| 규칙 제어기 (BC 시범용) | ego와 같은 관측만 쓰도록 만든다. 성향을 보고 판단하는 시범을 BC가 따라 하면, 관측만으로는 재현할 수 없는 정책이 된다 |
| GUI 색 | 영상용으로 색을 구분해도 되지만 관측에는 넣지 않는다 |

성향, 양보 결정, 반응 시간은 데이터셋의 정답 정보(privileged state)에만 기록한다.

## 6. ego 제어 구조

### 6.1 역할 분담: RL은 판단, 규칙 실행기는 횡방향 동작

RL이 횡방향 움직임까지 연속으로 직접 학습하면 행동·관측을 전부 새로 만들어야 하고, 남은 기간(최종발표 11/28) 안에 수렴시키기 어렵다. 그래서 역할을 나누기로 한다.

| 담당 | 내용 |
|---|---|
| **RL** | 종방향 가감속 (지금과 같음), 일반 차선변경, **끼어들기 시작 여부**, **포기 여부** |
| **규칙 실행기** | 앞머리 진입의 횡방향 움직임과 안전 연동 (팀 검토의 규칙 + 포기 규칙) |

### 6.2 행동 정의

`action[0]`(가감속)은 그대로 둔다. `action[1]`(차선 명령 −1/0/+1)의 의미를 상황에 따라 다음과 같이 해석한다.

| 상황 | 오른쪽(−1) | 유지(0) | 왼쪽(+1) |
|---|---|---|---|
| 오른쪽 차로가 흐르는 차로 | 일반 차선변경 | 유지 | 일반 차선변경 |
| 오른쪽 차로가 정체 줄 | **끼어들기 시작** (조건 충족 시) | 유지 | 일반 차선변경 |
| 앞머리를 걸친 상태 | 계속 진행 | 계속 진행 | **포기, 원래 차로로 복귀** |

### 6.3 규칙 실행기의 단계

| 단계 | 진입 조건 | 횡방향 동작 | 종료 |
|---|---|---|---|
| P0 대기 | — | 차로 중앙 | RL이 오른쪽(−1) + 시작 조건 충족 → P1 |
| P1 앞머리 진입 | ego 앞 범퍼가 뒷차 앞 범퍼보다 2m 이상 앞, 틈 ≥ 3m | 정체 차로 쪽으로 `d_nose`(1.0~1.4m)까지 이동 | 목표 깊이 도달 → P2 |
| P2 걸친 상태 | — | 깊이 유지 | 몸통 진입 조건 충족 → P3 / 포기 → P4 |
| P3 몸통 진입 | ego 뒷부분이 뒷차 앞 범퍼를 지났고 틈 ≥ 6.5m | 정체 차로 중앙까지 이동 | 진입 완료 → 일반 주행 |
| P4 포기 | RL이 왼쪽(+1), 또는 걸친 지 3초가 지나도 뒷차가 감속하지 않고 TTC < 기준 | 원래 차로 중앙으로 복귀 | 복귀 완료 → P0 |

- P3 조건은 팀 검토에서 충돌을 없앤 규칙을 그대로 쓴다. 이 조건이 충족되기 전에는 몸통을 넣지 않는다.
- P1~P3 동안에도 가감속은 RL이 맡는다. 앞머리 위치를 맞추는 타이밍도 학습 대상에 포함된다.
- 횡방향 이동은 `traci.vehicle.changeSublane()`으로 매 스텝 조금씩 한다.

### 6.4 관측 추가 (31차원 → 약 45차원)

기존 31차원은 그대로 두고 아래를 추가한다. 차원이 바뀌므로 기존 모델은 다시 학습해야 한다.

| 추가 관측 | 정규화 |
|---|---|
| 진출부까지 거리 | / 500m |
| ego의 차로 내 횡위치 | / 차로 폭 |
| 끼어들기 단계 (P0~P4) | one-hot 5 |
| 걸친 깊이 | / 차 폭 |
| 정체 차로 앞차: 뒤 범퍼까지 상대거리, 속도, 가속도 | / W, / vmax, / 최대 감속 |
| 정체 차로 뒷차: 앞 범퍼까지 상대거리, 속도, 가속도, 1·2스텝 전 가속도 | 같음 |
| 앞차와 뒷차 사이 틈 길이 | / 차 길이 |

뒷차의 가속도 이력은 "양보하는 중인지"를 추측하는 단서다. 성향 정보는 넣지 않는다.

### 6.5 보상 (초안)

| 항목 | 값 | 목적 |
|---|---|---|
| 진행 보상 | 경로상 진행 거리 / (vmax × 스텝) × 0.1 | 속도 보상 대신 사용. 정체 차로에서도 앞으로 가면 보상을 받는다 |
| 진출 성공 | +2 | |
| 충돌 | −5 | |
| 출구 놓침 | −5 | 충돌과 같은 수준. 끼어들기를 포기하고 본선으로 가는 것을 막는다 |
| 무리한 진입 | −1 / 회 | 비양보 뒷차가 `D_FORCE` 때문에 급제동한 경우 |
| 포기 | −0.05 / 회 | 넣었다 뺐다 반복 억제 |
| 흐르는 차로 저속 점유 | −0.01 / 스텝 | 1번 이상 차로에서 제한속도 50% 미만으로 머무는 시간. 끼어들기를 너무 오래 미루지 않게 한다 |
| `blocked_penalty` | 해제 | 정체 줄 안에서는 피할 수 없는 감점이라, 충돌로 일찍 끝내는 쪽을 배울 위험이 있다 |

값은 모두 초안이며, BC 학습 후 RL 미세조정 단계에서 조정한다.

### 6.6 학습 방법: 규칙 시범 → BC → PPO

1. 규칙 실행기에 "언제 시작하고 언제 포기할지"까지 규칙으로 정한 **규칙 기반 전문가**를 만든다. 이 전문가도 ego 관측만 쓴다.
2. 전문가로 주행 데이터를 모아 `train_bc.py`로 BC 정책을 학습한다.
3. BC 정책을 초기값으로 `train.py`(PPO)에서 미세조정한다. 성향 비율이 바뀌거나 비양보형이 많을 때 전문가보다 나은 판단을 배우는 것이 목표다.

이 흐름이면 수업에서 다룬 BC와 RL을 모두 쓰게 되고, 발표에서 "규칙 전문가 대비 개선"을 비교 지표로 보여 줄 수 있다.

### 7.3 평가 지표

**(1) 환경 유효성 — 에피소드마다 먼저 확인한다.** 통과하지 못한 에피소드는 AV 지표와 따로 집계한다.

| 지표 | 통과 기준 |
|---|---|
| 넘친 구간 길이 | ego 출발 시점에 목표 범위 안, 꼬리가 ego보다 뒤 |
| 다른 차로 흐름 | 0번 차로를 뺀 본선 차량 평균속도 ≥ 제한속도의 80% (ego가 막은 구간 제외) |
| 끼어들기 기회 | ego가 정체 차로 옆에 있는 동안 3m 이상 틈이 생긴 횟수 ≥ 3 |
| 순간이동 | 0회 |
| 일반 차량 수 | 도로망 내 일반 차량 수 (최소, 평균) 기록 |

**(2) AV 주행 성능**

| 지표 | 정의 | 목표 |
|---|---|---|
| 충돌률 | 충돌 에피소드 / 전체 | **< 5%** (C1~C3) |
| 진출 성공률 | 램프에 들어간 에피소드 / 전체 | ≥ 90% (C1~C3) |
| 출구 놓침률 | 진출부를 지나쳐 실패한 비율 | 기록, 낮을수록 좋음 |
| 근접 위험 | 횡간격 0.3m 미만 근접 횟수, 최소 TTC | 기록 |
| 무리한 진입 | 비양보 뒷차를 급제동하게 만든 횟수 | 0에 가깝게 |
| 포기 횟수 · 시도 횟수 | 에피소드당 평균 | 기록 |
| 끼어들기 소요 시간 | 정체 차로 옆 도착 ~ 진입 완료 | 기록 |
| 흐르는 차로 점유 시간 | 1번 이상 차로에서 제한속도 50% 미만으로 머문 시간 | 기록, 짧을수록 좋음 |
| 성향별 결과 | 끼어든 상대가 양보형·보통·비양보형일 때 각각의 성공률·충돌률 (정답 정보로 사후 분석) | 비양보형 앞에서 포기를 잘 하는지 확인 |

### 7.4 영상

최종발표의 30초 이상 주행 영상은 C1 또는 C5에서 고른다. 한 장면에 다음이 담기도록 한다.

1. ego가 흐르는 차로에서 정체 줄 옆에 도착
2. 줄 앞부분이 출발하며 틈이 벌어짐
3. 앞머리 진입 → 뒷차 감속 → 몸통 진입
4. 램프 진입 후 게이트 통과, 합류

가능하면 비양보 뒷차 앞에서 포기하고 다음 틈으로 들어가는 장면도 하나 넣는다.

### 10.2 SL2015가 일정 안에 안정화되지 않을 때의 대안

11/23 저녁까지 E1~E4에서 문제가 해결되지 않으면, LC2013을 유지하고 다음과 같이 단순화한다.

- ego가 정체 차로 옆에서 끼어들 의사를 보이면(옆에서 속도를 맞추고 일정 시간 대기), 뒷차가 5장의 양보 모델에 따라 감속해 **차 한 대가 들어갈 틈을 만든다**.
- 틈이 생기면 ego는 기존처럼 한 스텝 차선변경으로 들어간다.

앞머리 진입의 현실성은 떨어지지만, "뒷차 성향을 추측해 끼어들지 판단한다"는 문제의 핵심은 유지된다. 발표에서는 이 단순화를 한계로 밝힌다.

## 11. 팀에서 정해야 할 것

1. **R3 포함 여부:** 본선이 짧고 공유 구간 문제가 있어, 시간이 부족하면 R1·R2만으로 진행할 수 있다.
2. **넘친 구간 길이와 D 범위:** 위 값은 초안이다. 실제 한남IC 정체 길이를 지도·영상으로 확인해 근거를 붙이면 발표 설득력이 높아진다.
3. **양보 성향 비율과 확률:** 5.2절 표는 초안이다. 근거 자료를 찾을지, 실험값으로 둘지 정해야 한다.
4. **평가·영상에서 게이트 빠른 방출을 쓸지:** 램프 대기 시간을 줄이는 처리를 발표에서 어떻게 설명할지 정해야 한다.
5. **끼어들기에 대한 입장:** 현실에서는 진출로 앞 끼어들기를 비매너로 보는 시각이 있다. "줄 뒤로 갈 수 없는 상황에서 안전하게 끼어드는 법"이라는 문제 설정을 발표 앞부분에서 분명히 해 두는 것이 좋다.
